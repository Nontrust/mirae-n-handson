# 배치 점검

`$ARGUMENTS`를 로그 폴더로 쓴다. 비어 있으면 `pipeline-samples/batch-logs`를 쓴다.
적재 건수 CSV는 로그 폴더의 상위 폴더에서 `datamart-counts.csv`를 찾는다. 없으면 멈추고 경로를 묻는다.

## 점검 기준

1. **실행 여부** — 다른 날에는 매일 돌던 job이 그날 로그에 없거나, START만 있고 SUCCESS/FAILED가 없으면 이상.
2. **중복 실행** — 같은 날 같은 job의 SUCCESS가 두 번 이상이면 이상.
3. **적재 건수** — 같은 job의 직전 7일 평균에서 30% 넘게 벗어나면 이상. 0건은 무조건 이상.
4. **지연** — 소요 시간(`elapsed`)이 그 job의 평소 소요 시간(이상값을 뺀 중앙값)의 2배를 넘으면 이상.

## 규칙

- 날짜는 로그의 `date=`(대상 일자) 기준이다. 로그 파일명은 보통 그다음 날 실행분이다.
- 로그를 통째로 읽지 않는다. grep · awk · wc로 필요한 줄만 뽑는다.
- 평균 · 중앙값 · 편차율 같은 계산은 암산하지 말고 명령이나 스크립트로 한다. 계산 방법(직전 7행인지, 어떤 값을 뺐는지)을 리포트에 적는다.
- 이상마다 근거를 붙인다. 로그는 `파일명:줄번호`, 건수는 CSV의 해당 행.
- 로그에 없는 원인은 추측하지 않는다. 원인은 "확인 필요"로 두고 무엇을 더 봐야 하는지만 적는다. 로그에 없는 영향은 "추정"이라고 표시한다.
- 학생 식별자(`STU-…`) · 이메일 · 토큰은 리포트에 옮기지 않는다.
- 점검 기준 4개에 해당하지 않는 반복 WARN은 이상으로 세지 않고 참고로만 적는다.

## 진행 순서

1. 이상 후보를 표로만 먼저 보여 준다(날짜 · job · 점검 항목 · 근거). 파일은 아직 만들지 않는다.
2. 이상이 한 건도 없으면 "이상 없음" 한 줄만 답하고 파일을 만들지 않는다.
3. 이상이 있으면 아래 형식으로 `docs/batch-check/report.md`에 저장한다.

## 리포트 형식

- 맨 위 요약 한 줄: 점검 기간, 이상 건수(건수와 일자 수).
- 이상 목록 표: 날짜 / job / 점검 항목 / 근거 / 영향 추정 / 다음 확인 사항.
- 계산 기준 한두 줄.
- 맨 아래 "이상 없음으로 판정한 날짜" 목록.
