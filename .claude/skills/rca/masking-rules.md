# 마스킹 규칙

리포트를 저장하기 전에 아래 규칙을 본문 · 표 · 발췌 전부에 적용한다. 마스킹은 메모리에서만 하고, 대응표나 마스킹 전 사본을 파일로 남기지 않는다.

| 대상 | 처리 |
|---|---|
| IP 주소 | 역할 별칭으로 바꾼다. 구분이 필요하면 서버는 `API-1`, `API-2`, 교사 단말은 `교사단말A`, `교사단말B`처럼 별칭을 붙인다. 구분이 필요 없으면 `[IP]`로 쓴다. 같은 IP는 리포트 전체에서 같은 별칭을 쓴다. |
| 이메일 | `[EMAIL]` |
| 학생 식별자(`STU-…`) | `STU-***` |
| 토큰 (`Authorization` 헤더, Bearer, API 키, 세션 ID) | `[TOKEN]` |
| 비밀번호 · 접속 문자열 (`password=`, JDBC URL의 계정 · 호스트) | `[SECRET]` |

## 적용 방법

- 발췌 줄을 인용할 때 먼저 치환한 뒤 적는다. 치환 후에도 `파일:줄번호`는 그대로 둔다.
- 저장 후 리포트에서 IP · `@` · `STU-` · `Bearer` · `password`를 검색해 남은 원본 값이 없는지 확인한다.
- 리포트 마지막 줄에 종류별 적용 건수를 적는다. 예: `마스킹 적용: IP 4건(교사단말A~D) · 이메일 0건 · 학생 식별자 0건 · 토큰 0건 · 비밀번호·접속 문자열 0건`
