# item-bank-php 비즈니스 규칙 후보

> 대상: `legacy/item-bank-php`
> 먼저 읽음: `docs/item-bank/ARCHITECTURE.md`, `docs/item-bank/ERD.md`
> 원칙: 코드의 조건문·SQL로 직접 확인된 것만 "규칙"으로 올린다. 주석에만 있고 코드로 확인 안 되는 내용은 규칙으로 올리지 않고 비고에 "주석만 있음"으로 남긴다. 주석과 코드가 다르면 코드를 기준으로 쓰고 주석 내용은 비고에 남긴다.

**범위 관련 확인 사항**: 이 모듈에는 문항 "수정(UPDATE)" 기능이 없다. `register.php`는 신규 등록(INSERT)만 처리하며, 등록된 문항의 상태(`R`→`A`)를 바꾸거나 내용을 고치는 코드는 `legacy/item-bank-php` 어디에도 없다. 따라서 "수정 시 검증" 규칙은 코드에 없는 내용이라 작성하지 않았다.

## A. 문항 등록 검증 (register.php)

### BR-01
- **규칙**: 문항 제목(공백 제거 후)이 5자 미만이면 등록을 거부한다.
- **근거**: register.php:49-51
- **근거 코드**:
```php
if (mb_strlen($title, 'UTF-8') < 5) {
    $errors[] = '제목은 5자 이상 입력해야 합니다.';
}
```
- **확신도**: 확실
- **비고**: 매직 넘버 `5` — 매직 넘버 표 참조.

### BR-02
- **규칙**: 문항 제목이 200자를 초과하면 등록을 거부한다.
- **근거**: register.php:52-54
- **근거 코드**:
```php
if (mb_strlen($title, 'UTF-8') > 200) {
    $errors[] = '제목은 200자를 넘을 수 없습니다.';

```
- **확신도**: 확실
- **비고**: 매직 넘버 `200` — `item.title VARCHAR(200)`(db/mariadb/init/01-schema.sql:23)와 값이 같다. DB 컬럼 길이에 맞춘 것으로 보이나 주석·코드에 그 연결을 명시한 곳은 없다(추정).

### BR-03
- **규칙**: 지문(stem)이 빈 문자열이면 등록을 거부한다.
- **근거**: register.php:56-58

- **확신도**: 확실
- **비고**: 길이 상한 검증은 없음(스키마상 `stem`은 TEXT).

### BR-04
- **규칙**: 선택한 `unit_id`가 조회된 단원 목록(unit 테이블 전체)에 없으면 등록을 거부한다.

### BR-05
- **규칙**: 난이도 값이 정규식 `^[1-5]$`(1~5 사이 한 자리 숫자)와 일치하지 않으면 등록을 거부한다.
- **근거**: register.php:70-72

- **비고**: 매직 넘버 `1~5` — 매직 넘버 표 참조. search.php의 검색 조건에서 쓰는 난이도 범위와 값은 같지만 검증 실패 시 동작(등록 거부 vs 검색은 0건으로 진행)은 다르다.

### BR-06
- **규칙**: 등록 시 선택한 태그 중 태그 목록(tag 테이블)에 없는 값은 조용히 걸러내고, 등록 자체를 막지 않는다.
- **근거**: register.php:74-81
- **근거 코드**:
```php

    $validTagIds[] = (int)$tid;
```

- **비고**: 사용자에게 "일부 태그가 무시되었다"는 경고나 안내가 전혀 없다 — 무효 태그를 조용히 버리는 동작은 화면에 드러나지 않는다.

### BR-07
- **규칙**: 새로 등록된 문항은 상태를 `'R'`(검수중)로 저장하며, 검수가 끝나기 전까지는 검색 화면에 노출되지 않는다.
- **근거**: register.php:92-95, 116; db/mariadb/init/01-schema.sql:70 (`v_item_public`이 `status='A'`만 노출)
- **근거 코드**:
```php

```
- **확신도**: 확실
- **비고**: `R`을 `A`로 바꾸는(검수 승인) 코드는 이 모듈에 없다 — 별도 관리 화면/배치가 있는지는 미확인.

### BR-08
- **규칙**: 새 문항의 `id`는 `item` 테이블의 현재 최댓값에 1을 더해 트랜잭션 내에서 `FOR UPDATE` 잠금으로 채번한다.
- **근거**: register.php:85-90
- **근거 코드**:
```php
$res = $conn->query("SELECT COALESCE(MAX(id), 0) + 1 AS next_id FROM item FOR UPDATE");
```
- **확신도**: 확실
- **비고**: `item.id`는 스키마상 `AUTO_INCREMENT`가 아니다(db/mariadb/init/01-schema.sql:21) — 애플리케이션이 직접 채번하는 방식이라 동시 등록 시 `FOR UPDATE`로 레이스 컨디션을 막는 것으로 보인다(추정, 설계 의도에 대한 주석 없음).

## B. 문항 검색 조건 조합 (search.php `buildSearchQuery`)

### BR-10

### BR-11

### BR-13
- **규칙**: 난이도(`level`)를 지정하지 않으면 `level < 5`인 문항만 조회하여, 난이도 5(최상)는 기본 검색 결과에서 제외한다.

## E. 검색 조건 조합 (search.php `buildSearchQuery`, 교차 검증으로 추가)

### BR-26
- **규칙**: 검색 조건에 키워드·단원·난이도·태그를 함께 지정하면 각 조건은 SQL `WHERE` 절에 `AND`로만 이어붙으므로, 지정한 모든 조건을 동시에 만족하는 문항만 조회된다(조건을 `OR`로 묶는 코드는 없다).
- **근거**: search.php:44, 98, 118, 215, 218, 226, 244-245
- **근거 코드**:
```php
$where    = " WHERE 1=1";
...
$where .= " AND (title LIKE ? OR stem LIKE ?)";      // 키워드
...
$where .= " AND unit_code = ?";                       // 단원
...
$where .= " AND level < 5";                           // 난이도(빈 값)
$where .= " AND level = ?";                           // 난이도(1~5 지정값 · 범위 밖 값)
...
$where .= " AND EXISTS (SELECT 1 FROM item_tag it JOIN tag t ON t.id = it.tag_id"
        . " WHERE it.item_id = v_item_public.id AND t.name = ?)";   // 태그
```
- **확신도**: 확실 (`$where`가 `" WHERE 1=1"`(44행)으로 시작한 뒤 각 조건 블록이 전부 `.= " AND ..."` 형태로만 덧붙는 것을 확인했고, `OR`로 조건 블록을 묶는 코드는 없다 — 키워드 조건 내부의 `title LIKE ? OR stem LIKE ?`는 한 조건 안의 대안일 뿐 조건 블록 간 결합과는 다르다)
- **비고**: 코드에 이를 명시한 주석은 없다 — 교차 검증(CX-01)으로 새로 추출한 규칙.
