# 전사 개발자 규칙 후보 (플랜)

- 주 스택: `data-infra`
- 상태: 후보안. 기존 설정이나 Hook은 변경하지 않는다.
- 확인 기준: 이 작업 루트와 하위 저장소에서 `.claude/settings.json` 및 Claude용 `hooks/`는 발견되지 않았다. 접근 가능한 Jira·Confluence의 장애 보고서·운영 배포 기준·Jira 이슈를 읽어 아래 후보에 반영했다.

| 규칙 | 종류(deny / ask / allow / Hook) | 적용 범위(공통 또는 스택 코드) | 막는 사고 또는 허용 이유 |
| --- | --- | --- | --- |
| `rm -rf`, `Remove-Item -Recurse -Force`, `git clean -fdx`, `git reset --hard` 등 광범위·복구 곤란 명령을 실행하지 않는다. | deny | 공통 | 소스·산출물·로컬 작업물의 비가역적 삭제를 막는다. |
| `git push --force`, `--force-with-lease`는 대상 브랜치·대체 이력·영향 범위를 설명하고 사용자의 명시적 승인을 받은 뒤에만 실행한다. | ask | 공통 | 공동 브랜치 이력 및 동료 커밋 손실을 막는다. |
| 운영 DB 접속, 운영 데이터에 대한 직접 쓰기, 백업·복구·복제본 전환은 작업 대상과 롤백 방법을 제시하고 승인을 받은 뒤에만 실행한다. | ask | 공통 | 운영 데이터 손상과 복구 지연을 막는다. |
| dummy 데이터임이 DB명·접속 문자열·환경 변수로 명시적으로 검증된 로컬/테스트 DB에서만 파괴적 SQL을 허용한다. 검증할 수 없으면 운영 데이터로 취급한다. | allow | 공통 | 테스트·개발 작업은 유지하면서 실데이터 오판을 막는다. |
| dummy가 아닌 DB의 `DELETE`, `TRUNCATE`, `DROP`, `ALTER`, DB·스키마·테이블·인덱스·권한 등 메타데이터 변경은 사용자 승인 없이는 실행하지 않는다. SQL 파일을 통한 간접 실행도 포함한다. | ask | 공통 | 복구 시간이 긴 데이터 삭제와 스키마 훼손을 막는다. |
| `.env`, 인증서·개인키, 클라우드 자격 증명, 비밀 관리 파일과 그 원문을 읽거나 출력하지 않는다. | deny | 공통 | 시크릿의 대화·로그·외부 서비스 유출을 막는다. |
| 파일 수정·명령 실행 뒤 변경분과 커밋 대상에서 키·토큰·비밀번호·개인키 패턴을 탐지하고, 탐지 시 외부 전송과 커밋을 차단한다. | Hook | 공통 | 실수로 포함된 시크릿의 반출을 차단한다. |
| 코드·로그·DB 덤프·고객 데이터를 외부 URL, SaaS, 메신저, 이슈·문서 도구로 전송하기 전에는 대상·항목·마스킹 여부를 설명하고 승인을 받는다. | ask | 공통 | 개인정보·운영정보의 무단 외부 전송을 막는다. |
| 운영 배포 전에는 Ready for Release 상태, 검증·운영 산출물의 동일성, DB 변경 및 롤백 방안, Batch 영향 확인을 모두 기록하고, 배포 후 주요 기능·오류 로그를 검증해 Jira·Confluence 이력을 남긴다. | Hook | 공통 | 검증되지 않은 변경·DB 롤백 누락·배포 이력 단절을 막는다. |
| `kubectl get`은 읽기 전용으로 허용한다. `apply`, `delete`, `patch`, `edit`, `replace`, `scale`, `rollout restart`, `exec` 및 리소스 상태를 바꾸는 모든 Kubernetes 명령은 사용자 승인 뒤에만 실행한다. | ask | data-infra | EKS의 워크로드·설정·서비스 중단과 원격 명령 실행 사고를 막는다. |
| `aws` CLI의 상태 변경 명령(`create`, `update`, `put`, `modify`, `delete`, `terminate`, `start`, `stop`, `reboot`, `attach`, `detach`, `restore` 등)은 사용자 승인 뒤에만 실행한다. `get` 계열 조회는 허용한다. | ask | data-infra | EKS·EC2 및 연결된 AWS 리소스의 의도치 않은 변경·비용·장애를 막는다. |
| S3 객체의 일괄 삭제, `sync --delete`, 삭제 마커 제거, 버킷 수명주기·삭제 정책 변경은 대상 버킷·prefix·예상 객체 수·버전관리·복구 절차를 제시하고 사용자 승인을 받은 뒤에만 실행한다. | ask | data-infra | 실제 S3 객체·신규 콘텐츠 유실과 장시간 복구를 막는다. |
| S3 파괴·수명주기 변경 사전 Hook은 객체 목록/영향 건수, `--dryrun` 또는 동등한 사전 검증, 버전관리·복구 가능 여부, 승인 증적을 확인하고 하나라도 없으면 중단한다. | Hook | data-infra | 삭제 범위 오인과 복구 불가능한 콘텐츠 유실을 실행 전에 차단한다. |
| Kubernetes·AWS 변경 명령의 사전 Hook은 계정·리전·클러스터·네임스페이스·대상 리소스와 변경 명령을 표시하고 승인 상태가 없으면 중단한다. | Hook | data-infra | 잘못된 환경과 대상에 적용되는 사고를 실행 전에 막는다. |
| DB 파괴적 SQL 사전 Hook은 dummy 환경 검증 결과, 영향 대상, 백업/복구 계획, 승인 여부를 확인하고 하나라도 없으면 중단한다. | Hook | 공통 | 삭제·스키마 변경을 승인과 복구 준비 없이 실행하는 일을 막는다. |
| 다른 서비스의 운영 DB·스키마에 직접 연결하는 신규/변경 작업은 데이터 소유자의 승인과 API 또는 명시적 스키마 계약, 연결 풀·배치 실행 계획을 갖춘 뒤에만 진행한다. | ask | 공통 | 스키마 변경·비합의 배치·과도한 DB 풀로 인한 교차 서비스 장애를 막는다. |
| 운영 컨테이너의 메모리/CPU 요청·제한, JVM 힙 설정, DB 커넥션 풀 또는 배치 동시성 변경 시에는 사전 Hook으로 환경별 값·상한·모니터링 지표·롤백 설정을 확인한다. | Hook | data-infra | JVM 기본 설정·스트림/커넥션 고갈로 인한 CPU 포화·502/504 장애를 막는다. |

| 운영 DB에서 대량 `UPDATE` 또는 `INSERT … SELECT`는 예상 영향 건수와 트랜잭션/롤백 계획을 제시하고 승인받는다. | ask | 공통 | 삭제가 아니어도 대량 데이터 훼손·잠금을 일으킬 수 있다. |
| 인프라 변경 전후에 대상 조회, 변경 계획(dry-run/plan), 헬스체크·롤아웃 상태 확인을 강제하고 결과를 작업 기록에 남긴다. | Hook | data-infra | 실제 장애 회고에서 확인되는 대상 오인·검증 누락을 재발 방지 규칙으로 전환한다. |
| S3 수명주기 또는 삭제 대상 변경은 샘플 prefix에서 복구 리허설을 마친 뒤 단계적으로 적용하고, 적용 뒤 신규 콘텐츠의 존재·접근성을 검증한다. | Hook | data-infra | 삭제 정책이 신규 객체까지 제거한 실제 사고를 재발 방지한다. |

## 주의

| 규칙 | 종류(deny / ask / allow / Hook) | 적용 범위(공통 또는 스택 코드) | 막는 사고 또는 허용 이유 |
| --- | --- | --- | --- |
| `kubectl`·`aws`를 `get` 외 전부 차단하는 규칙은 `describe`, `list`, `logs` 같은 읽기 진단까지 막는다. 조회 전용 명령은 별도 allow 목록으로 확장할지 합의한다. | Hook | data-infra | 장애 조사 속도를 불필요하게 떨어뜨리지 않는다. |
| `kubectl exec` 일괄 차단은 긴급 진단을 막을 수 있으므로 deny 대신 승인형으로 유지한다. | ask | data-infra | 원격 실행 위험과 장애 대응 필요를 함께 다룬다. |
| DB명에 `test`가 들어간다는 이유만으로 dummy로 판정하면 운영 복제본을 오인할 수 있다. 연결 문자열·계정·환경 표식을 함께 검증해야 한다. | Hook | 공통 | 실데이터 예외 처리의 우회를 막는다. |
| 시크릿 탐지 Hook을 잠금 파일·테스트 fixture·암호화된 파일에 그대로 적용하면 오탐으로 개발을 막을 수 있다. 검토된 최소 예외와 만료 기한을 둔다. | Hook | 공통 | 보안을 낮추지 않으면서 오탐을 관리한다. |

## Jira·Confluence 반영 계획
git status --short

1. 확인한 장애 보고서와 관련 Jira 이슈의 원인·실행 명령·누락된 검증·영향 범위를 위 표의 승인 규칙과 사전 Hook에 반영했다.
2. 사고 재현 명령과 정상·차단 사례를 Hook 테스트로 만들고, 보고 전용 모드에서 오탐을 검증한 뒤 차단 모드로 전환한다.
3. 실제 `.claude/settings.json`과 `hooks/` 위치가 제공되면, 기존 규칙을 중복 없이 표에 병합하고 구현 차이를 별도 제안으로 정리한다.
